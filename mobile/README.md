# 793 Pints — Mobile (iOS + Android)

Cross-platform mobile front-end built with **Kotlin Multiplatform Mobile (KMM)** and **Compose
Multiplatform**. All UI, business logic, networking, and view-models are written **once in Kotlin**
inside the `shared/` module and run natively on both Android and iOS.

## Build & run

### Pre-requisites

| Tool | Version |
|---|---|
| JDK | 17 |
| Gradle wrapper | 8.10.2 (will be downloaded by `gradle wrapper`) |
| Android Studio | Hedgehog or newer (with Android SDK 35) |
| Xcode | 16+ (for iOS) |

### One-time setup

```bash
cd mobile
# Generate the Gradle wrapper if not present
gradle wrapper --gradle-version 8.10.2
```

### Android

```bash
cd mobile
./gradlew :androidApp:installDebug
```

The dev base URL points at `http://10.0.2.2:8080/api/v1` — that's the loopback the
Android emulator uses to reach the host machine running the Spring backend
(`./mvnw spring-boot:run` from the project root).

### iOS

1. Build the shared framework (one-off; rebuilds automatically when sources change):
   ```bash
   cd mobile
   ./gradlew :shared:linkDebugFrameworkIosSimulatorArm64
   ```
2. Open `mobile/iosApp/iosApp.xcodeproj` in Xcode (Xcode-project file is **not** generated by
   Gradle; create one once and add the framework to the target's *Frameworks, Libraries, and
   Embedded Content* with **Embed & Sign**, set its search path to
   `$(SRCROOT)/../shared/build/bin/iosSimulatorArm64/debugFramework`).
3. ⌘R to launch the simulator. The dev base URL is `http://localhost:8080/api/v1`, valid for
   the iOS Simulator (not for a physical device — see "Configuration" below).

> **Recommended alternative:** install JetBrains' "Kotlin Multiplatform Mobile" plugin in
> Android Studio and use *File → New → New Project → Compose Multiplatform App* once to scaffold
> a working Xcode project, then **delete its `shared/`** and reuse this one. Xcode-project XML
> doesn't fit nicely in source control without manual fix-ups so we don't generate it here.

### Configuration

Per-platform base URLs live in `shared/build.gradle.kts → buildkonfig`. Override per build by
passing `-PANDROID_BASE_URL=https://api.example.com/api/v1` to Gradle, or by adding flavor
configs (`targetConfigs.create("prod") { … }`).

### Backend CORS / cleartext

The Spring backend already allows arbitrary origins. For dev:

* **Android emulator** — cleartext to `10.0.2.2` is whitelisted in
  `androidApp/src/main/res/xml/network_security_config.xml`.
* **iOS simulator** — cleartext to `localhost` is whitelisted in
  `iosApp/iosApp/Info.plist` via an `NSAppTransportSecurity → NSExceptionDomains` entry.
  Strip this dict from any release build.

## Architecture summary

* **One `ViewModel` per React page** (`androidx.lifecycle.ViewModel` exposed via the
  Compose-Multiplatform Lifecycle artifact). Each VM holds a `MutableStateFlow<UiState>` consumed
  by its Composable through `collectAsStateWithLifecycle()`.
* **Auth flow** — token persisted via `TokenStore` (Keychain/EncryptedSharedPreferences). Ktor's
  `defaultRequest` injects the bearer header on every call. Any 401 / 400 fires
  `AuthRepository.logout()` which clears the token, flips `AuthStatus` to
  `Unauthenticated`, and emits on `logoutEvents`. `App.kt` listens and `popUpTo(0)` →
  `Route.Login`.
* **Cask state machine** — `domain/logic/CaskStateMachine.kt` is a pure Kotlin port of
  `frontend/src/pages/CellarPage.tsx#getNextState/refreshCaskState/getCooldown` plus a
  `remainingMillis` helper for live countdowns.
* **Cask cooldown timer** — `CellarViewModel` (TODO, see checklist) should run a
  `tickerFlow` (1 Hz) that calls `CaskStateMachine.refresh(cask)` whenever
  `remainingMillis(cask) <= 0`, mirroring the `setInterval` in the React page.
* **Navigation cache** — `NavCache` replaces React Router's `location.state`. Stash members,
  cellars, member-images here keyed by `orgId`; downstream screens read from cache then refetch
  in background. **The same bug we fixed in `OrganisationPage.tsx`** (treating the cache as
  "real" only when access level is set) applies here — gate cache-trust on the presence of
  `accessLevel`.

## Known limitations

1. **No Xcode project under source control.** Generate once with the JetBrains KMM plugin or use
   `kotlin-cocoapods` integration (uncomment the plugin in `shared/build.gradle.kts` and add a
   `Podfile` in `iosApp/`).
2. **`Compose Multiplatform` text input on iOS** is still maturing — IME / autofill behaviour
   may differ from a native UIKit `UITextField`. Wrap in an `expect`/`actual` if you hit issues.
3. **Multipart upload with the Darwin engine** has been observed to buffer large bodies into
   memory — fine for ≤2 MB profile pictures.
4. Push notifications, deep linking, and offline support are out of scope.
